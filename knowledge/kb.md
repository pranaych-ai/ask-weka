## 🎯 Accountable

*"Accountability is the glue that ties commitment to results."* — Bob Proctor **What it means at WEKA**

  

  - We get to results in spite of any challenge; we're proactive problem-solvers who act with urgency.
  - We don't make excuses or finger-point; we're transparent about mistakes and improve from them.
  - We ensure our peers are aligned with the results we require, and we don't accept mediocre performance.
  - We focus on impact and outcomes, not activity, and push for continuous improvement. **Why it drives us forward:** drive impact (dependable), support each other (committed), move the company forward (impactful). **In action**
  - **Proactive responsibility** — step up without being asked; own gaps, anticipate issues, act fast.
  - **Radical transparency** — share wins and mistakes honestly; speak up, listen, avoid spin.
  - **Continuous improvement** — refine, automate, and level up how we work.
  - **Follow-through** — see things to the finish line, even when it's uncomfortable or not "your job."

## 🦁 Brave

*"The best way to predict the future is to create it."* — Abraham Lincoln **What it means at WEKA**

  

  - Choose courage over comfort; what's right over what's fun, fast, or easy.
  - Challenge directly (not behind a peer's back); respectfully speak up and say what we think.
  - Move fast and take smart, calculated risks; optimize for innovation, creativity, and excellence.
  - Choose transparency even when uncomfortable; challenge the status quo; keep asking for feedback.

  - **10 company-paid** parental leave days — first 5 immediately after birth, remaining 5 within 6 months.

  - Secrets avoidance: use a secrets manager (Vault, GCP Secret Manager, AWS KMS) or env vars for local/dev + platform secret managers for prod; enable repo push protection (§5.1.3); if a secret is accidentally committed, notify CISO + rotate immediately.
  - SAST/SCA/Secret Scanning (§5.1.3): all three mandatory in CI/CD for every in-scope repo (incl. internal tools, AI-assisted code); exceptions need explicit CISO approval. SAST = static code security review pre-merge; SCA = dependency vulnerability scanning; Secret Scanning + push protection = blocks credential commits.
  - Repo visibility (§§5.1.9-11): private by default; public requires written justification + CISO approval; only a defined authorized group can create/configure public repos; visibility reviewed annually.
  - AI coding assistants (Copilot, ChatGPT) (§5.11, POL-17): allowed if the AI tool is IT/Security-approved; AI-produced code follows the same SDLC (no hardcoded secrets, SAST/SCA, code review, publishing gates); never paste WEKA source code/sensitive data into a public AI tool.
  - Security code review (§5.8.2): required for critical custom code, performed by an app-security expert other than the author; web apps reviewed against OWASP; Chief Engineering Officer ensures this happens pre-release.
  - Vulnerability tracking (§5.1.4, POL-02 §12.5): analyzed for likelihood/impact, remediated per severity-based SLAs (Vulnerability Discovery Procedure); critical/high pen-test findings need owner+target date within 30 days; unmitigated vulns need formal documented CISO risk acceptance, not verbal sign-off.
  - Prod data in test (§5.9.1): prohibited — dev/test environments logically+physically separated from prod; use synthesized/anonymized data; cloud dev/staging follow same default-private posture as prod.
  - Publishing gates (§5.10.2), required before any new app/service/API even internal: 1) security review approved by CISO/designated reviewer; 2) assessed against secure coding guidelines + SAST/SCA/secret-scanning toolchain; 3) approved through formal Change Control. Applies to all teams, all app types including AI-assisted/homegrown.
  - Training (§5.5): annual for developers/non-R\&D builders; new hires complete within 30 days of joining; covers secure design, secrets hygiene, common vulnerabilities.

  - No sharing work laptop with family members, even briefly (§4.1.4, POL-03 §4.3) — risk of keyloggers, compromised sites, accidental deletion, unwanted monitoring trail.
  - Personal laptop on WEKA office network (§4.1.3): not allowed — guest network only.

  - Personal software (§4.3.1): only IT-approved software/extensions/utilities — submit a request.

Section 6 — AI Usage Policy (WEKA-IS-POL-17), newest/most likely to evolve:

  

  - Using AI tools (§7, TPRM at §11): only IT/InfoSec-approved tools; use an already-approved tool for your use case or submit a request for a new one — don't just start with a personal account.
  - Personal AI subscriptions (§13): cannot be used for company work — non-negotiable (personal accounts often train on prompts, no audit trail/data protection contract).

## \[IT KB\] Linux Unsigned kernel workaround

URL: <https://app.notion.com/p/62c55d53dda54f399afea84fb042e65b> Category: Software | Coverage: Documented | Difficulty: Advanced | Tags: Troubleshooting, Software | Topic: Devices & Endpoints Error: "Your kernels are unsigned. This system will fail to boot in a secure boot environment" (grub won't update since kernel is unsigned). Fix steps: 1) Find current kernel version: uname -r. 2) List installed images: ls /boot/. 3) Find package owning that image: dpkg -S /boot/vmlinuz-\<version\>. 4) List matching packages: dpkg --list | grep \<version\>. 5) Extract package names: dpkg --list | grep \<version\> | awk '{print $2}'. 6) Purge old kernel: sudo apt-get purge $(dpkg --list | grep \<version\> | awk '{print $2}'). 7) Run apt update then apt upgrade. TL;DR: if apt update shows "damaged link" for vmlinuz.old/initrd.img.old, run sudo update-grub to fix. No warning shown = no problem.
